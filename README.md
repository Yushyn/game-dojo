# Game Dojo — підлаштуй стопу під чобіт

HTML5 Canvas + чистий JS, без збірки. Supabase для лідерборду, Netlify для хостингу.

## Правила

Після «Почати» сцена порожня. Далі йде вступ: спершу на пʼєдесталі зʼявляється
сам чобіт (`intro.bootSeconds`), потім він зникає, на його місці зʼявляється
контур (`intro.outlineSeconds`), і разом із контуром зверху опускається нога.
Коли вступ закінчився — стартує робочий час раунду (`round.totalSeconds`).

Контур береться з файлу, вказаного в `outline` у списку `boots`. Якщо його
немає, гра малює силует із самого чобота.

Праворуч показують чобіт. Через `previewSeconds` він зникає, і далі гравець
по памʼяті мне стопу пензлем, щоб вона повторила його форму. Коли спливає
`totalSeconds`, чобіт накладається на стопу і гра рахує, наскільки силуети
збіглися. Понад поріг — очки й наступний чобіт, нижче — той самий ще раз.

Біля пʼяти є **опорна точка**: у цьому колі пензель не діє взагалі, а далі
від центру діє дедалі сильніше.

## Запустити локально

ES-модулі не працюють через `file://`, потрібен сервер.
У VS Code: розширення **Live Server** → права кнопка по `index.html` →
**Open with Live Server**. Або в папці проєкту `npx live-server`.

В адресі має бути `http://127.0.0.1:…`, а не `file:///C:/…`.
Якщо щось не так — відкрий `check.html`, він перевірить усі файли.

## Що де лежить

- `src/tuning.js` — **файл для геймдизайнерів.** Таймери, пороги, очки,
  список чобіт, опорна точка, пензель, кольори, тексти.
- `src/config.js` — ключі Supabase і розмір полотна (1920×1080).
- `src/game.js` — рушій: деформація, опорна точка, порівняння форм, раунди.
- `src/main.js` — звʼязок сторінки з грою, лідерборд.
- `src/screens.js` — титул, завантаження, меню, перемикання екранів.
- `src/db.js` — лідерборд. Якщо база недоступна, гра все одно працює.
- `assets/foot.png`, `assets/boot1.png`, `assets/boot2.png` — картинки.
  Усі з прозорим фоном: фон рахувався б за частину силуету.
- `assets/background.png` — фон сцени, 1920×1080. Якщо файлу немає,
  гра просто малює темне тло і працює далі.

## Як додати новий чобіт

1. Поклади PNG у `assets/`. Фон обовʼязково **прозорий** — інакше він
   рахуватиметься за частину чобота і зіпсує підрахунок.
2. Допиши рядок у `boots` всередині `tuning.js`.
3. Відкрий консоль браузера (F12). При запуску гра друкує, скільки відсотків
   збігу дає **недоторкана** стопа для кожного чобота. Поріг має бути помітно
   вищим за це число, інакше раунд зарахується тому, хто нічого не робив.

## Як посунути стопу на пʼєдесталі

Блок `image` у `tuning.js`. Розмір і місце рахуються по самій стопі, без
прозорих полів навколо, тому числа не попливуть при заміні картинки.

- `heightPercent` — яку частину висоти екрана займає стопа
- `standX` — де по горизонталі вона стоїть
- `standY` — на якій висоті підошва (саме підошва, не центр)
- `shadow`, `shadowWidth`, `shadowHeight` — мʼяка тінь під стопою

## Як влаштована деформація

Оригінал ніколи не змінюється. Поруч живе «карта зміщень»: для кожної точки
результату записано, з якого місця оригіналу брати колір. Пензель править цю
карту, а картинка збирається за нею наново щокадру. Тому якість не псується
від сотні мазків, а Ctrl+Z миттєвий.

## Як рахується збіг

На початку раунду чобіт один раз прикладають до незімʼятої стопи і **фіксують**
на цьому місці до кінця раунду. Прикладається він по довжині стопи, підошвою
на ту саму землю; якщо конкретний чобіт сидить не так, у списку `boots` є
`scale`, `offsetX` і `offsetY`. Далі гравець бачить його саме там, у тій самій
позиції й тому самому розмірі, у якій він потім і звірятиметься.

**Лінія відрізу.** Нога вища за чобіт, і гомілка над халявою в нього не влізе
ніколи. Тому все, що вище верху халяви, у площу не зараховується — ні для
стопи, ні для чобота. На екрані це пунктирна лінія. Вимикається через
`compare.cutAboveBoot`.

Відсоток = спільна площа силуетів поділена на загальну. Система координат
нерухома, тому має значення і форма, і куди саме ти цю форму посунув.

Плюс такого підходу: щоб додати чобіт, достатньо PNG. Нічого розмічати руками
не треба, форма звіряється сама.

## Підключити Supabase

1. Supabase → SQL Editor → вставити `schema.sql` → Run.
2. Project Settings → API Keys → скопіювати Project URL і **publishable** key.
3. Вписати обидва в `src/config.js`.

Секретний ключ (`sb_secret_*`) у фронт не потрапляє ніколи.

## Деплой

Netlify → Add new site → Import an existing project → GitHub → вибрати репо.
Build command порожній, publish directory `.` — це вже прописано в `netlify.toml`.
